# BijyonTools UI ガイド

画面を作る・直すときの考え方と決まり。2026-11-26〜27 に全アプリ（DEV を除く）を見直したときに bi が決めたことをまとめたもの。
新しいアプリも、既存の画面の直しも、ここに合わせる。手順は `.claude/skills/bijyon-ui/SKILL.md`。

## 1. 考え方

- **パーツを置いた感じにしない。** 部品（ボタン・入力欄・色）は daisyUI 5 でそろっている。ばらつくのは並べ方。並べ方の約束（下の型と共通の約束）を守れば、中身が違っても同じサイトに見える。
- **画面は利用場面から決める。** 「誰が・いつ・何をしに開くか」を先に書き、その画面で一番大きく見せるもの（主役）を決める。
- **UI で伝わることは文字で説明しない。** 位置・色・形・状態・列名・ボタン名で言えていることは書かない。使い方や計算の前提は Guide（`public/guide.js`）の各アプリの説明へ。ただし特殊な入力（Scouter の Wild Hunter 欄など）の補足は画面に残す。

## 2. 画面の型（5つ）

新しいアプリは、どれか1つを選んで組む。

| 型 | 骨組み | 例 |
| --- | --- | --- |
| ハブ | 同じ形のカードを並べ、カードから各ツールへ | Character Manager の Dashboard |
| 入力→結果 | 左に入力、右に結果。結果は入力前も表の形を出す | Party Scouter、EXP Simulator、Symbol、Quanah |
| 入力→結果（タブ） | 入力が多いときは Input と Result をタブで分け、「計算する」で Result に自動で移る（移ったら一番上から見せる） | Scouter |
| 参照表 | 条件・追加の1行、その下に全幅の表 | Cheat Sheet、KMS Videos、EXP Tracker、Community Members |
| 読み物 | 中央に読みやすい幅で本文。ここだけ見出し＋説明文があってよい | Journal、Guide |
| ボード | 左に候補、右に組む場所 | Party Builder の Builder |

## 3. 共通の約束

1. **1列＝1面。** 列ごとに面（`.mm-face`）を1つ置き、中は見出しつきの区切り（`.mm-sec`）と線1本で分ける。箱の中に箱を作らない。枠で囲うのは、そこだけ別の物として扱いたいとき（キャラカード、モーダル）だけ。
2. **見出しは1種類。** `.mm-sec-h` の `h3`（14px 太字 白）、補足は横の `span`（11px 灰）、右端の数字は `em`、右寄せのボタン群は `.mm-sec-r`。英大文字＋字間のラベル（EQUIP、CHARACTER INFO など）は使わない。
3. **アプリ名の見出し＋説明文は置かない。** 名前はサイドバーとタブが言っている。
4. **結果は空でも形を見せる。** 表の列と行の名前を出し、値の所だけ空か「—」。「〇〇を入れると出ます」だけの空き枠にしない。
5. **primary ボタンは1画面に1つ。**
6. **余白は本文の左右上 24px、面と面の間 16px。** iframe（Party Builder）も同じにする。
7. **言葉。** 本文は日本語。アプリ名・タブ名・ゲームの固有名（職業名、ボス名、難易度、地域・ダンジョン名、Main/Sub/Mule、サーバー名、カードの帯 HEXA・UPGRADE・SCOUTER・SYMBOL など）は英語のまま。全部日本語にはしない。
8. **ヘッダーのタブは英語。** アプリの上部バーのタブも、モーダルの中のタブも英語（例 Input／Result、Progress／Order Map／Curve／CT、Gear／Pieces／Jewels）。本文で「〇〇タブ」と書くときも英語の名前で。
9. **タブのあるモーダルは、タブを切り替えても枠の大きさを変えない**（高さ固定 `h-[94vh]`、中は `flex-1 min-h-0` でスクロール）。
10. **キャラに紐付くのはダッシュボードのカードから開いたときだけ。** サイドバーから開くアプリ単体は仮入力用。ヘッダーで対象キャラを選ぶ形にはしない。

これまでの決まりもそのまま守る:

- アプリ単位は左のサイドバー、アプリの中の切り替えはヘッダー。検索条件や入力オプションはヘッダーに入れず本文に置く。
- 範囲の決まった値はプルダウンかボタン。数字は等幅・右寄せ・幅固定で、値が変わっても周りがずれない。
- 強調は色と太字。色の意味は固定（メルは緑、Kronos 緑、Challenger 紫、難易度の色）。色（ハイライト）は選ぶ・オンオフする所だけで、ただの入力欄には付けない。
- 影や段差で立体にしない。ダークテーマのみ。

## 4. 共通部品（`public/style.css`）

| クラス | 役目 |
| --- | --- |
| `.mm-face` | 1列＝1面。子の間に線1本 |
| `.mm-sec` | 面の中の区切り（padding 12px 16px、中は gap 8px） |
| `.mm-sec-h` | 区切りの見出し行（`h3`・補足 `span`・右の数字 `em`・右のボタン群 `.mm-sec-r`） |
| `details.mm-sec` ＋ `.mm-caret` | 一度決めたら触らない設定を畳む。見出しの横に要約を出す（Upgrade Priority の「スコア重み・設定」） |
| `.mm-cols` / `.mm-col` | 面の中を2列に（48rem 以上、間は縦線） |
| `.mm-face.mm-row` | 面の中を N 列に（`--mm-n`、既定 3） |
| `.mm-mark` | 区切りの見出しの左に付ける8pxの色の四角（種類の色） |
| `.mm-note` | 11px の注記 |
| `.sc-q-grid` / `.sc-q-f` | 2列の入力欄と、その上の小さなラベル |

例:

```html
<div class="mm-face">
  <section class="mm-sec">
    <div class="mm-sec-h"><h3>デイリー</h3><span>セラス（Lv240）はデイリーなし</span></div>
    <div class="sc-q-grid">
      <label class="sc-q-f"><span>倍率</span><input class="input input-sm w-full font-mono"></label>
    </div>
  </section>
  <section class="mm-sec">…</section>
</div>
```

## 5. 作ったら確かめること

- 型を1つ選び、共通部品で組んだ。
- 箱の中に箱がない。見出しは共通の書式だけ。英大文字のラベルがない。
- アプリ名の見出し＋説明文がない。使い方・計算の前提は Guide に書いた。
- 結果が空のときも表の形が見える。
- primary は1つ。範囲の決まった値はプルダウンかボタン。
- 本文は日本語、タブ名・固有名は英語。
- タブのあるモーダルの大きさがタブで変わらない。
- `APPS`（`public/script.js`）・README のアプリ表・Guide を更新した。
- スクショをスクロール 0 で撮り、上端のそろい・はみ出し・折り返し（ラベルが2行になって入力欄がずれる等）を自分で見てから送った。撮り方は `tools/shoot-all.js`。
